# Meme Launchpad Pro — Backend v2.1

Multi-tenant meme-token launchpad API: Node 20, TypeScript, Express, MongoDB, Redis/BullMQ, Solana.
See `CHANGELOG.md` for everything fixed since v2.0.

## Quick start (Docker)

```bash
cp .env.example .env
# 1. generate secrets and paste into .env
openssl rand -hex 48   # JWT_SECRET
openssl rand -hex 48   # JWT_REFRESH_SECRET (different)
# 2. replace every CHANGE_ME_* (Mongo/Redis passwords: keep MONGODB_URI / REDIS_URL in sync)
# 3. set PUBLIC_SITE_URL, CORS_ORIGINS, BOOTSTRAP_* and a private SOLANA_RPC_URL
docker compose up -d --build
docker compose run --rm api node dist/scripts/seed.js   # creates tenant + admin
curl localhost/health
```

The app refuses to start in production while secrets still contain `CHANGE_ME`.

Put your frontend build in `public/` (it is copied into the image and served by nginx and the API).
`public/uploads` is a shared Docker volume.

## Local dev

```bash
docker compose up -d mongo redis      # exposed on 127.0.0.1 only
# in .env use localhost URIs:
#   MONGODB_URI=mongodb://mlp:<pw>@localhost:27017/meme_launchpad_pro?authSource=admin
#   REDIS_URL=redis://:<pw>@localhost:6379
#   NODE_ENV=development  DEMO_MODE=true
npm install
npm run seed:dev && npm run dev        # + npm run dev:worker in a second terminal
npm test
```

## DEMO_MODE
- `true`: seed adds demo content; if providers fail, clearly labelled simulated data is served (`source: "Simulated demo feed"`, `isDemo: true`, `X-Data-Source: demo`).
- `false` (production default): never fabricates data; market/holder endpoints return `503` when providers are down.

## API (all under `/api/v1`, envelope `{ success, data, meta? }`)

| Area | Endpoints |
|---|---|
| Public | `GET /public/:slug/bootstrap` · `/memes` · `/challenges` · `/announcements` · `/tokenomics` · `/roadmap` |
| Market (published tokens only) | `GET /public/:slug/market/:mint` · `/market/:mint/history?range=1H\|6H\|24H\|7D\|30D` · `/holders/:mint` |
| Auth | `POST /auth/register` · `/login` · `/refresh` (rotating) · `/logout` · `/logout-all` · `GET /auth/me` |
| Wallet | `POST /wallet/challenge` → sign `message` → `POST /wallet/verify` |
| Memes (auth) | `GET /memes` · `/mine` · `/pending` · `POST /memes` · `POST\|DELETE /memes/:id/like` · `POST /memes/:id/share` · `/report` · `PATCH /memes/:id/moderate` |
| Challenges | `GET /challenges` · `POST /challenges/:id/enter` · admin: `POST /challenges` · `PATCH /:id/end` |
| Referrals | `POST /referrals/:slug/track` (visit/share) · `GET /referrals/me/link` · `/me/stats` · `/leaderboard` |
| Uploads | `POST /uploads?folder=memes\|branding\|avatars` (multipart field `file`) |
| Analytics | `POST /analytics/:slug/event` · `GET /analytics/:slug/overview` |
| Admin | `/admin/overview` `branding` `tokens` (+`/:id/verify` `publish` `unpublish` `feature`) `tokenomics` `roadmap` `integrations` `audit-log` `reports` `team` `analytics` `referrals` |
| Super admin | `GET/POST /super/tenants` · `PATCH /super/tenants/:id` |
| Health | `GET /health` (Mongo + Redis) |

Frontend change vs v2.0: market/holders calls move to `/public/:slug/market/:mint`, `/public/:slug/holders/:mint`
(the unscoped `/market/*` routes were removed on purpose). Send `Authorization: Bearer <accessToken>`; refresh tokens rotate, so always store the new one.

## Production checklist
1. Real secrets, passwords, `CORS_ORIGINS`, `PUBLIC_SITE_URL`; `DEMO_MODE=false`.
2. Use a **private Solana RPC** — public RPC blocks `getTokenLargestAccounts`, which holder data needs. Set `BIRDEYE_API_KEY` for price history and total-holder counts.
3. TLS: issue certs with certbot and enable the commented redirect/443 block in `nginx.conf`.
4. Commit `package-lock.json` (generated by your first `npm install`) so Docker builds use `npm ci`.
5. S3 (`UPLOAD_PROVIDER=s3`) if you run more than one API host.
6. Back up the `mongo_data` volume; run Mongo as a replica set if you later need transactions.
7. Scale: `docker compose up -d --scale api=2` (limits/sessions are Redis-backed); run a single `worker`.
8. Monitor `/health` (503 = Mongo or Redis down).

## Known limitations
- Holder data is the top 20 token accounts aggregated per owner (RPC limit), with total-holder count only if Birdeye is configured (otherwise flagged `holderCountIsSample`).
- Price history needs Birdeye; without it, history is empty (or demo in DEMO_MODE).
- Likes are per-account; sybil accounts are still possible — add email verification / wallet gating if that matters.
